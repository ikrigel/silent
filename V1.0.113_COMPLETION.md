## Problems Solved

### Issue 1: Airplane Mode Not Found on Paginated QS Panels (v1.0.112+)

**Before v1.0.113:**
- Samsung SM-A515F (Android 14, Hebrew): QS panel has 3 pages, airplane mode toggle on page 2/3
- Robot automation would scroll down (ACTION_SCROLL_FORWARD) but couldn't reach horizontal pages
- Result: "Airplane,mode toggle not found" failure 100% of time
- Same issue affected calibration mode airplane mode confirmation

**Root Cause:**
- QS panel pages arranged horizontally (like ViewPager), not vertically
- ACTION_SCROLL_FORWARD scrolls DOWN within container, not LEFT/RIGHT to next page
- Need ACTION_SCROLL_BACKWARD (opposite direction) for horizontal pagination

**Solution v1.0.113 — 3-Scroll Strategy:**
Implemented in both `toggleByAnyLabel()` and `clickByAnyLabel()`:

```kotlin
// Attempt 1: Vertical scroll FORWARD on root
var scrolled = root.performAction(AccessibilityNodeInfo.ACTION_SCROLL_FORWARD)

// Attempt 2: Vertical scroll FORWARD on scrollable node
if (!scrolled && scrollableNode != null) {
    scrolled = scrollableNode.performAction(AccessibilityNodeInfo.ACTION_SCROLL_FORWARD)
}

// Attempt 3: Horizontal scroll BACKWARD (moves to next page in horizontal pagination)
if (!scrolled && scrollableNode != null) {
    scrolled = scrollableNode.performAction(AccessibilityNodeInfo.ACTION_SCROLL_BACKWARD)
}
```

**Features:**
- Enhanced `findScrollableNode()` helper finds next scrollable container in accessibility tree
- 7-pass retry loops (0–6 attempts) with 600ms delays between passes
- Detailed logging for each scroll attempt (true/false result)
- Discovers which direction succeeds on each device

**Impact:**
- Airplane mode automation now works on Samsung Quick Settings
- Handles both vertical (Settings screens) and horizontal (QS panels) pagination on same device
- Supports future multi-page UI scenarios

**Files Modified:**
- `android/app/src/main/java/com/ikrigel/silent/WEARobotAccessibilityService.kt`
  - `toggleByAnyLabel()`: Lines 310–340 (3-scroll strategy with logging)
  - `clickByAnyLabel()`: Lines 234–264 (identical 3-scroll strategy)
  - `findScrollableNode()`: Helper function for scrollable container discovery

### Issue 2: Playwright Test Strict Mode Violations (v1.0.113)

**Before v1.0.113:**
- GitHub Actions test failure: `strict mode violation: getByText(/Info entry|Info/) resolved to 2 elements`
- Regex pattern `/Info entry|Info/` matched both:
  1. Log entry with text "Info entry"
  2. Level filter chip labeled "Info"
- Playwright strict mode rejects ambiguous selectors

**Root Cause:**
Tests used regex patterns that were too broad, matching multiple UI elements

**Solution:**
Replace regex patterns with exact text selectors:

```typescript
// Before
await expect(page.getByText(/Info entry|Info/)).toBeVisible();

// After
await expect(page.getByText('Info entry')).toBeVisible();
```

**Changes:**
- Line 163–176: `level chips display correctly` test
  - Changed `/Info entry|Info/` → `'Info entry'`
  - Changed `/Error entry|Error/` → `'Error entry'`
  - Changed `/Verbose entry|Verbose/` → `'Verbose entry'`

**Impact:**
- All Playwright tests now pass in GitHub Actions
- CI/CD pipeline no longer blocked by test failures
- Tests more specific and maintainable

**Files Modified:**
- `tests/logs.spec.ts` (lines 163–176)

### Issue 3: Scheduler Restoration Checkboxes Hidden (v1.0.113)

**Before v1.0.113:**
- User enables only "Silence WEA alerts" quick action
- Expected: "Restore previous state" and "Unsilence WEA on end" checkboxes should appear
- Actual: Checkboxes remain hidden
- Root cause: Form wasn't watching `silenceWEAOnStart` field

**Problem Code:**
```typescript
// Line 61: Missing silenceWEAOnStart from watch list
const useAirplaneMode = watch('useAirplaneMode');
const robotRecordingId = watch('robotRecordingId');

// Line 219: Condition didn't include silenceWEAOnStart
if (robotRecordingId || useAirplaneMode || silenceWEAOnStart) {  // ❌ undefined!
  // Show unsilenceWEAOnEnd checkbox
}
```

**Solution:**
Add `silenceWEAOnStart` to watch list and update visibility conditions:

```typescript
// Line 61: Add to watch list
const silenceWEAOnStart = watch('silenceWEAOnStart');

// Line 219: Include in condition for unsilenceWEAOnEnd visibility
if (robotRecordingId || useAirplaneMode || silenceWEAOnStart) {
  // Now correctly shows checkbox
}

// Line 231: Include in condition for restoreOnEnd visibility
if (useAirplaneMode || robotRecordingId || silenceWEAOnStart) {
  // Now correctly shows checkbox
}
```

**Why It Works:**
- React Hook Form's `watch()` subscribes component to field changes
- Without watch, component doesn't re-render when field changes
- Adding to watch list → component re-renders → conditional rendering evaluates with current value

**Impact:**
- Users can now enable restoration options when using "Silence WEA" alone
- All three quick actions now correctly trigger restoration UI
- Better user experience: clear options for what happens at schedule end

**Files Modified:**
- `src/pages/Scheduler/SchedulerForm.tsx` (lines 61, 219, 231)
